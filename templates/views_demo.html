Database Views (Virtual Tables & Abstraction)

A View is a virtual table whose contents are defined by an underlying SQL query. Views do not store physical copies of data, but dynamically retrieve them.

View 1: Product_View
Security Abstraction: Hides sensitive Purchase_Price from cashier / viewer roles.
Security View
Underlying SQL Definition:
CREATE OR REPLACE VIEW Product_View AS
SELECT 
    Product_ID, 
    Product_Name, 
    Category,
    Brand,
    Selling_Price, 
    Available_Quantity
FROM PRODUCT;

View 2: Bill_Summary_View
Aggregation Abstraction: Combines bills and counts total items purchased.
Summary View
Underlying SQL Definition:
CREATE OR REPLACE VIEW Bill_Summary_View AS
SELECT 
    B.Bill_ID,
    B.Bill_Name,
    B.Payment_Method,
    B.Total_Amount,
    COUNT(BP.Product_ID) AS Total_Items
FROM BILL B
LEFT JOIN BILL_PRODUCT BP ON B.Bill_ID = BP.Bill_ID
GROUP BY B.Bill_ID, B.Bill_Name, B.Payment_Method, B.Total_Amount;

Advantages of Views Demonstrated:
  • Data Security: Users querying Product_View can never see confidential purchase rates or profit margins.
  • Query Simplicity: Instead of writing multi-table LEFT JOIN and GROUP BY queries repeatedly, the front-end simply calls SELECT * FROM Bill_Summary_View.
  • Logical Data Independence: Changes to underlying storage schemas can be shielded from frontend applications.
